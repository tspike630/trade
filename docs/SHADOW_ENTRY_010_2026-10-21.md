## Code change (opt-in, default unchanged) — decision_engine/run.py
- `--output-db PATH`: SignalBus writes decision_log to PATH; indicators still read from `--db`
  (dexscreener.db, read-only adapter). Without the flag, output = `--db` as before.
- `--shadow-liq-cohorts`: uses `ShadowCohortRisk` (subclass of RiskManager). For buys it stamps
  `liq_bucket` = `present`/`missing` and `budget_regime`. Missing-liquidity buys are NOT dropped
  (control cohort); present-liquidity buys still go through the normal $50k floor + cooldown.
  Refuses to start unless `--output-db` != `--db`.
- `budget_regime`: read at signal time from env `X_HOURLY_BUDGET_REQUESTS`, else from the crawler
  `.env` (read-only, single key). unset/20 → `20h`, 4 → `4h`, other N → `Nh`.

## Store (for execution layer wiring)
File: `/workspace/dexscreener-crawler/decision_shadow_entry_010.db`, table `decision_log`
(same DDL as main): `id, ts (UTC ISO), strategy_id, action, chain_id, token_address, size_pct,
reason, risk_passed, mode='dry_run', purpose='live_candidate', raw_json`.
Cohort tags live in `raw_json.extras`: `liq_bucket`, `budget_regime`, `liquidity_usd`
(null for missing), `jev_strength`, `pairCreatedAt`, ...
Example: `SELECT id, json_extract(raw_json,'$.extras.liq_bucket'), json_extract(raw_json,'$.extras.x_budget_regime') FROM decision_log;`
c_exit_shadow_run can consume it with `--decision-db <this file> --crawler-db dexscreener.db
--shadow-db <its own new db>` (it filters purpose=live_candidate, which these rows carry).
WARNING: rows are purpose=live_candidate, so never point the MAIN execution loop
(`execution.run --db`) at this file.

stop-loss share of losing trades not higher than the main book's.
