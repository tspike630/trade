# 指标 / 因子时间序列算子化（M-3）

> 硬规则。写 indicator 或 factor 的时间序列代码时适用，包括执行 AI 新写的检测器。  
> 不改权重，不新开运行时打分，**不算有效性**。`INDICATORS_WEIGHT_*` 保持 **0**。

来源：调研报告 §五 M-3；AQuA（arXiv 2608.12841）。

---

## 规则

1. **窗口在 t 收口。** 每个时间序列算子只能使用截止当前 bar 的数据。滚动窗口含标记为 t 的这一根，不含任何更晚的 bar。
2. **禁止日合计 / 未来分母。** 不得用当日总成交量、当日总笔数、会话结束后才知道的 total，或任何要看到 t 之后才算得完的量，去做分子或分母。同样禁止 `shift(-k)`、负向 lag、居中滚动窗口（`center=True`）。
3. **允许表，或显式因果窗口。** AI 编写的指标 / 因子代码必须二选一：只用下面的允许算子，或在代码旁写明因果窗口（右端 = t，长度在 t 已知）。不允许「先写公式，再靠另一轮 LLM 审查来抓未来函数」。

本表是写代码时的约束，不是运行时拦截器，也不给因子打分。

## 允许算子

| 算子 | 因果条件 |
|------|----------|
| lag / `shift(k)` | k ≥ 0，只看过去 |
| rolling mean / std / sum / min / max / rank | 右对齐，窗口在 t 结束，不居中 |
| diff / pct_change | 只用当前 bar 与过去 |
| ewm | 递推只看见 ≤ t 的历史 |
| 时点快照字段 | 该行 `recorded_at ≤ t`。行上的 `volume_h1` / `volume_h24` 若是该快照时刻的**回看**成交量，可以用；不得改成事后补上的自然日总量 |

## 为何做成结构约束

AQuA 记过一起真实 look-ahead：LLM 作者和 LLM 审查都漏掉了「当日总成交量」分母里的日内未来信息。事后改成固定算子注册表，因果在组合下闭合。互审不够，所以这里写成硬规则。

## 与现网

`indicators/technical.py` 的 `volume_strength` 用快照上的 `volume_h1`（缺则 `volume_h24 / 24`），窗口相对最新快照往回切。这是回看字段，不是本规则禁止的日合计未来分母。本文不改该实现。新代码不要把 `volume_h24` 换成尚未走完的自然日总量。
